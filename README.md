# Villagers' Savior

Minecraft Java 26.2 的 Fabric 模组：保护村民、赢得信任，并在饥饿时向村民请求真实库存中的食物。

## 环境与安装

- Minecraft **26.2**、Java **25**。
- Fabric Loader **0.19.5 或更新版本**、Fabric API **0.161.0+26.2 或兼容更新版本**。
- 客户端与服务端均安装模组及 Fabric API。单人游戏只需安装到客户端。
- 将 `build/libs/villagers-savior-1.0.0+mc26.2.jar` 放入目标实例的 `mods/`。

按住 **V**，使用空手右键村民请求食物。可以在“选项 → 控制 → 按键绑定”中改绑。松开请求键后，右键仍使用原版交互。完整规则见 [机制描述](Villagers_Savior_mechanics.md)。

## 实现规则

- 击杀敌对生物：死亡点球形 24 格内每位村民分别获得声望，每个玩家与村民组合每日最多 5 点。默认普通敌对生物权重 1；苦力怕、末影人、唤魔者、卫道士、猪灵蛮兵为 2；劫掠兽、监守者、凋灵、末影龙为 3。
- 修复铁傀儡：仅实际恢复生命时有效；32 格内村民各 +1，每个玩家与村民组合每日上限 3 点。
- 制造铁傀儡：实际放置雕刻南瓜/南瓜灯或使用剪刀雕刻南瓜生成铁傀儡的玩家获得奖励；32 格内村民各 +5。村民 64 格内现存铁傀儡超过 5 个时不奖励，**不减少负面 Gossip**。发射器、命令或无法确认制造者的生成不归因给附近玩家。
- 村庄铁傀儡死亡：只处理非玩家制造、死亡时位于原版村庄内且最终伤害源为具体玩家的铁傀儡。32 格内村民正面声望 -10，7 日内连续击杀的负面惩罚递增；第 6 次起额外增加重大负面声望。环境死亡与玩家制造的铁傀儡不处罚。
- 袭击胜利：原版 `heroesOfTheVillage` 记录的实际参战者获得中心 64 格内村民的重大正面声望 +2，同玩家与村庄 7 日内只奖励一次。
- 普通赠粮：计算真实库存营养值与原版声望，保留 20 点营养，以有界背包算法找到预算内营养值最大的组合。没有凭空生成食物。
- 紧急救济：饱食度低于 6 且正常赠粮失败时，无视声望和保留库存，赠送营养值最低的 1 个食物；同玩家与村庄共享 168000 tick 冷却，成功生成掉落物后才记录冷却。
- 服务端校验空手、实体存活、交互距离、视线及交易占用；每位玩家请求间隔至少 20 tick，以限制网络重复请求。掉落物面向请求玩家，并指定该玩家为拾取目标。

## 村庄与持久化

床、工作站、钟等具有原版 `PoiTypeTags.VILLAGE` 标记的 POI，间距不超过 64 格时组成连通区域。查询从交互或事件位置 64 格内最近的 POI 开始；POI 区域保存稳定标识，区域合并保留较晚的冷却记录，已登记 POI 的移除/区域分裂不清除已有冷却。未识别到村庄的村民仍可普通赠粮，但无法使用按村庄记录的紧急救济。超过 4096 个 POI 的异常连通网络不发放依赖村庄标识的奖励。

每日上限按服务器单调 `gameTime / 24000` 计数；7 日窗口为 168000 个服务器游戏 tick。睡觉或 `/time set` 改变日夜显示不会绕过限制，服务器停机期间不计时。

历史保存在各维度的世界 SavedData `villagers_savior:history` 中，包含每日奖励、滚动击杀历史、冷却及村庄标识。重启继续使用；不同维度相互独立。模组奖励写入原版真实 Gossip，保留原版声望上限、衰减、传播与交易价格机制。原版丢弃新建 1 点 Gossip 的行为在本模组奖励写入时作了局部处理，确保描述中的 +1 能实际生效。

## 构建与验证

```sh
./gradlew build
./gradlew runIntegrationTest -PacceptMinecraftEula=true
```

运行测试服前需同意 [Minecraft EULA](https://www.minecraft.net/eula)。测试服使用 `run-test/` 独立平坦世界，仅绑定本机地址与随机端口，不使用真实存档。测试模组不会打包到发行 jar 中。

自动检查涵盖预算边界与库存最优解、死亡/修复/制造 hook、球形范围、日上限、滚动惩罚、冷却与序列化、库存扣除、紧急救济、网络请求校验及袭击胜利。验证结果见 `build/verification.txt`（若存在）与 `run-test/test-result.txt`。

真实客户端按键、显示、交互手感及第三方模组兼容性需要客户端验证；服务端测试不能替代这些验证。
